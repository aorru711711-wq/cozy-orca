# Voyage upgrade — shared worker contract

User wants four Grok Build workers in Orca implementing: crew sailor per working agent, anchor crew badge, 1–3 masts/sails as crew grows; elapsed active sailing time + longer wake/day-night clock; crates and gold completion sparkles; remaining-task horizon buoys passing on completion; red flag/storm for real failure, quiet flare for waiting; one line pill `● Working · 3 crew · 1h 24m · ✓7/10`. Keep cozy motion, no audio, no notifications, no agent controls, E: storage only.

All workers share the current checkout. No commits, resets, new worktrees, or nested agents. Read your live Orca preamble and report worker_done correctly. Source directories of E:/orca are read-only reference material. Never touch another worker's owned files. Send interface concerns via Orca messages.

## Stable interfaces (implement these names)

1. `aggregate(payload, now)` in status.cjs keeps existing kind/label/needsInput/agents behavior and extends sanitized agent rows with `name` (displayName, agentType, or 'Agent'), `task` (taskTitle or empty; never raw prompt/tool text), `startedAt` (stateStartedAt), `failed` (explicit mainAgent.outcome === 'failure'). Preserve IDs. Return `hasError` when any explicit failed agent is reported. Unknown/stale/incomplete snapshots remain unavailable. No reported failure may look like a success completion.
2. New `src/voyage.cjs` exports `VoyageTracker`. Constructor accepts optional persisted plain state; `update(snapshot, now=Date.now())` returns the snapshot with `crewCount`, `crew` (working sanitized rows), `sailingMs`, `completedCount`, `totalCount` (number or null), `remainingCount` (number or null), `completionSerial` (monotonic), `completionAt` (epoch milliseconds, 0 until new completion), `hasError`. It exposes `serialize()` for durable cumulative time/counters. Time accumulates only across continuously observed working intervals, never waiting, disconnected, unknown, sleep gaps, or app downtime. Count each task ID once, not each poll. Fallback without task inventory: count only observed nonpaused/nonfailed working-to-done agent turns, label scope as observed turns, denominator null. Switching task sources must not double count. Preserve baseline StatusTracker glow behavior and old tests.
3. Poller gets a successful task inventory from new task source adapter and attaches `snapshot.taskProgress = { known:boolean, items:[{id,runId,state,title}], runIds:[] }` before `onStatus`. `state` uses canonical `pending|working|completed|failed|cancelled`. Unknown inventory must not invent a total or imply completion. Task errors do not discard valid fleet work status. Task adapter uses the same native executable, execFile, no shell, hidden windows, five-second timeout and bounded buffers. Discover real nonlegacy Orca runs, inspect task-list per run, track runs with unfinished work (not unrelated all-completed historic runs at startup), retain tracked runs for this app session, refresh every ~10 seconds with no overlapping subprocesses. Reject partial/unverifiable task listings. Do not expose task specs/results/prompts in display data.
4. Main process applies existing `StatusTracker` via poller, then `VoyageTracker` in onStatus; load/save voyage state atomically under existing E: dataDir (separate voyage.json). Persist at bounded intervals and shutdown. Renderer IPC includes ONLY safe stats above and existing display fields; never spread raw snapshots or agent details. Main owns integration; do not add a circular import.
5. `CozyScene.draw(ctx, display, timeSeconds)` accepts those stats. Defaults must keep original callers working. Crew/masts/crates/buoys are visual representations; counts are truthful in label. At 144×72, avoid overlap: allow at least 8 individually distinct sailor positions; overflow can be visually grouped with exact anchor badge rather than covering the boat with unlimited sprites. At most 3 masts, up to 6 visible crate stacks/buoys with exact numeric counters for higher values. Completion events animate from completionAt/serial, once, even while other work continues; reduced motion uses static markers. Waiting uses steady flare, never sound. Failed/unknown conditions distinct. Preserve simple pixel grid and 12fps renderer.
6. Renderer uses one clean bottom pill: status, crew, active sailing duration and task progress. Example text `Working · 3 crew · 1h 24m · ✓7/10`; status dot is separate existing span. If total unknown use `✓7` with a tooltip explaining observed turns; do not show `/0`, guessed totals, or overflow. At default 288px width, compact font/spacing enough to fit this example; long labels may use concise status `Working` with attention communicated by flare and tooltip. Duration live ticks without resetting across polls. No new microphone/network/data privileges.
